# 项目说明

`58API-Image-Gen` 是 [58api.net](https://58api.net/) 的图像生成插件，支持 Codex、Claude Code、ZCode、DeepSeek Harness、Trae 等能运行本机 Node.js 命令的 Agent 客户端。当前版本为 `3.1.3`，一个插件调用 58API 全部生图模型（GPT Image、az-gpt-image、Gemini / Nano Banana、Grok Imagine、Seedream、Midjourney）。

模型能力边界的唯一来源是本仓库里的模型清单 `plugins/58api-image-gen/skills/58api-image-gen/scripts/image-models.snapshot.json`。它同时是插件内置快照，也是插件联网刷新时读取的地址（GitHub raw：`https://raw.githubusercontent.com/blackxl/58API-image-gen/main/plugins/58api-image-gen/skills/58api-image-gen/scripts/image-models.snapshot.json`）。插件读取这份清单决定端点、传法和放行的参数，不在代码里写模型表。上新模型或改参数只改这份清单并推送到 `main`；只有出现新的请求方式（清单里新的 `protocol` 或 `size.param`）才需要发插件新版本。

## 模型清单

- 加载顺序：本机缓存 `~/.58api/image-models.json`（24 小时内有效）→ 联网拉取清单 → 过期缓存 → 内置快照 `scripts/image-models.snapshot.json`。只有本来就要联网的命令（付费运行、`--list-models`、`--refresh-models`、`--set-model`）才联网；`--dry-run`、`--get-config`、`--self-test`、`--job-status` 只用缓存或快照。联网拉取超时 8 秒，拉不到（例如国内网络访问 GitHub raw 不稳定）时自动用缓存或内置快照，不影响出图。
- 清单经 `catalog.mjs` 的 `sanitizeCatalog` 校验：`schemaVersion` 必须是 1；端点只能是 `/v1/images/generations`、`/v1/images/edits`、`/v1/chat/completions`，域名固定为 `generate.mjs` 里的 `API_ROOT`（`https://58api.net`）；不合格的模型条目被丢弃，整份清单不可用时改用缓存或快照。清单里的 `apiBase`、`docsBase`、`docs` 字段插件不使用。
- `resolveRequestPlan` 把 `--aspect`、`--resolution`、`--quality`、`--background`、`--output-format` 按条目换算成请求字段（`size` 像素 / `aspect_ratio`+`resolution` / 档位 / `--ar` / `image_config`），不支持的取值在付费前报错。`selectEditVariant` 按参考图来源（本地文件 / URL）和张数选出编辑请求方式并检查上限。
- `--list-models` 调用免费的 `GET /v1/models`，按 Key 标出 `available`。`--model` 指定清单没有、但 Key 能用的生图模型时，`inferEntry` 生成保守条目：只发提示词和参考图，不发尺寸和质量参数。
- 更新清单：上游模型能力有变化时，用最新清单覆盖 `image-models.snapshot.json`，再把文件开头的 `apiBase`、`docsBase` 改回 `https://58api.net`、`source` 改回 `58API image model catalog`，推送到 `main` 即可，所有用户 24 小时内自动生效。

## DeepSeek Harness 插件包

根目录的 `package.json` 让 DeepSeek Harness 的「添加插件」可以直接安装本仓库（`github:blackxl/58API-image-gen`）：`dsh.bundle.patch` 把 `dsh/cordis.patch.yml` 合进 profile，`dsh/index.js` 用 DSH 内置的 `@deepseek-ai/dsh-skill-filesystem` 挂一个名为 `58api-image-gen`、只扫描 `plugins/58api-image-gen/skills` 的技能来源（`includeDefaultRoots: false`）。技能只有 `plugins/` 下这一份，DSH 读的就是 Claude Code、Codex、ZCode 用的同一个 `SKILL.md` 和脚本。

- `@deepseek-ai/dsh-skill-filesystem` 是可选 peer 依赖，由 DSH 自带，安装时不下载。
- 展示信息：DSH 从 `locale/en.json` 的 `meta.title` / `meta.description` 读标题和简介，从 `package.json` 的 `icon` 读图标（相对路径、SVG/PNG/JPEG/WebP、不超过 256 KiB），图标用 Codex 的 `assets/plugin-logo.png`。
- ZCode 的图标、显示名读 `.claude-plugin/marketplace.json` 插件条目的 `icon`（只认 `https://` 地址，填 GitHub main 上 `plugin-logo.png` 的原始文件地址）和 `displayName`；Claude Code 忽略这两个字段。
- **简介所有客户端保持同一句**：`package.json`、`locale/en.json`、`.claude-plugin/plugin.json`、`.claude-plugin/marketplace.json`、`.codex-plugin/plugin.json`（`description` 和 `interface.shortDescription`）、`agents/openai.yaml` 的 `short_description`；改简介要一起改，`dsh/package.test.mjs` 会检查。

## 配置契约

配置文件默认位于 `~/.58api/image-gen.json`（环境变量 `API58_CONFIG_DIR` 可改目录）。环境变量 `API58_KEY` 优先于配置文件，只在本次进程中使用、不写盘。插件公开使用一个 `auto` 分组令牌。

本插件**不读取任何其它 API 站点插件的配置文件**，避免把别的站点的 Key 发到 58API：`LEGACY_CONFIG_PATHS` 为空，旧版镜像路径只指向 `~/.codex/58api-image-gen-config.json`（不存在时不做任何事）。本插件没有任何启用的 Key 时（`API58_KEY` 也没设），会读取同目录下 58API 视频插件的 `~/.58api/video-studio.json` 顶层 `apiKey`，只在内存里使用、不写进 `image-gen.json`。

模型优先级：单次 `--model` > 保存的 `model` > `gpt-image-2`。分辨率优先级：单次 `--resolution` > 快速 / 批量模式保存的 `resolution` > 顶层 `resolution` > 清单的 `defaultResolution`。

真实 Key 只允许保存在用户本机配置，不得出现在源码、文档、提交、Release、日志或聊天回复中。`--get-config` 只显示活动 Key 的脱敏摘要。

## API 与安全边界

- 端点、上传格式和参考图上限由模型清单决定：Images API 模型用 `POST /v1/images/generations` / `POST /v1/images/edits`（multipart 或 JSON）；Gemini 用 `POST /v1/chat/completions`，比例和分辨率写在 `extra_body.google.image_config`。
- 不调用 `/v1/responses`，失败后不换端点、不换模型。
- 按像素出图的模型（`size.param = size`）在付费请求前检查 16 像素对齐、最大边 `3840`、最大宽高比 `3:1`、总像素 `655360～8294400`，并保留提示词末尾的画幅提醒和本地 PNG 裁切；其它模型按返回结果原样保存。
- 不支持的比例、分辨率、参数和参考图张数在本地终止，不发起付费请求。
- 已受理或状态未知的请求使用 `[NO-AUTO-RETRY]`，不得自动重发；用户明确授权后可作为一次新的付费请求重新提交。
- 请求超时 600 秒。失败按阶段报告：连不上服务器（`request was not sent`，未发出、未扣费，可自动重试）；提交后状态未知（`stage: submit`）；已收到响应但读取失败（`stage: read-result`，已扣费）；结果图下载失败（`stage: download`，已扣费）。
- 结果是链接时，下载前先把链接写入输出目录的 `*.pending-download.json`，免费重试 3 次（间隔 2 秒、5 秒），成功后删除；仍失败时保留该文件，`--retry-download <文件>` 只下载、不发新的付费请求。
- `--dry-run` 不要求 Key、不调用付费 API、不输出图片 Base64。
- 每次付费运行在 `~/.58api/image-gen-jobs/<任务号>.json` 写提交记录：每个请求发出前记为 `submitting`，收到响应后记 HTTP 状态，结束时记为 `saved` / `not-sent` / `rejected` / `unknown` / `billed-not-saved` / `empty-result`。进程被客户端超时强行结束时，`--job-status` 会报告为 `interrupted`（`[NO-AUTO-RETRY]`，可能已扣费）。
- 两张及以上图片必须由一次插件进程通过 `--count`、`--repeat`、`--batch-inline` 或 `--batch` 调度，避免 Auto 模式为每张图片重复申请外网执行审批。

```powershell
node plugins/58api-image-gen/skills/58api-image-gen/scripts/generate.mjs --self-test
node plugins/58api-image-gen/skills/58api-image-gen/scripts/generate.mjs --list-models
node plugins/58api-image-gen/skills/58api-image-gen/scripts/generate.mjs --resolve-size --model gpt-image-2 --aspect 16:9 --resolution 4K
node plugins/58api-image-gen/skills/58api-image-gen/scripts/generate.mjs --model gemini-3-pro-image --prompt "probe" --aspect 3:4 --resolution 2K --dry-run
node plugins/58api-image-gen/skills/58api-image-gen/scripts/generate.mjs --model grok-imagine-image --prompt "probe" --aspect 21:9 --resolution 2K --dry-run
npm run check
```
